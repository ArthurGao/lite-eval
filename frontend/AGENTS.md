# frontend — Agent Guide

The Viewer: a single-page app that reads lite-eval's run records through the backend API. Read the root `AGENTS.md`
first; this file adds frontend rules. Design: `docs/lite-eval-design.md` §10 (pages, data, packaging), §8 (what
comparisons and triage mean), §5 (the contracts it shows).

## Layout (E3)

```
frontend/
  package.json                # pnpm; React + Vite + TS, TanStack Router (file routes, hash history) + Query,
                              # Radix primitives + Tailwind 4 (no shadcn CLI), lucide icons
  openapi-ts.config.ts        # client from ../backend/openapi.json (committed by the backend)
  src/client/                 # GENERATED by @hey-api/openapi-ts — never edit by hand
  src/routeTree.gen.ts        # GENERATED by the router plugin on build — committed
  src/data/source.ts          # the one door to data: liveSource (API) and embeddedSource (an export)
  src/routes/                 # index (Runs), runs.$suite.$runId.{index,cases.$caseId,triage}, compare,
                              # datasets.{index,$name}, trends
  src/components/             # ui, marks (RunMarks, IntervalStrip, CaseStrip), cases, detail, annotate, trend
  src/lib/                    # verdict (delta reading, span layout), format, keys (J/K), theme
  src/styles.css              # tokens (light/dark), Tailwind theme
  e2e/                        # Playwright; data from backend tests/e2e/viewer_fixture.py on port 8722
```

`pnpm build` writes one JS and one CSS file to `dist/` (no code splitting: `lite-eval report --html` inlines
them); `backend/scripts/build_frontend.py` copies it into `backend/src/lite_eval/server/static/`. Visual
direction: `PRODUCT.md`, `.impeccable/surfaces/frontend-src.md` and `DESIGN.md` at the repository root.

## Rules

1. **The OpenAPI spec is the only contract.** Call the API only through the generated client. If an endpoint is
   missing, add it to the backend first.
2. **No statistics in the browser.** Metrics, deltas, significance, warnings and "one case = x points" come from the
   API; the UI shows them. It never recomputes or rounds a number into a different conclusion.
3. **Show doubt as prominently as the number**: a non-significant delta is shown as such (not green / red), a run
   with warnings or a synthetic dataset is marked on every page that lists it, errors are counted next to scores.
4. **Regressions first**: comparison lists show newly failing cases before newly passing ones.
5. **The only write is an annotation** (miss triage, "label wrong"), sent with the per-process
   `X-Lite-Eval-Token` the page was served with (design §18.10). No edits to runs or datasets.
6. **Dense data tool**: tables and side-by-side views first; load the `design-direction` skill before choosing the
   look; charts follow the `dataviz` skill. Every list filters and paginates; long inputs and outputs collapse.
7. **No native `alert` / `confirm` / `prompt`**; use the dialog components.
8. Works offline as an exported single HTML file (design §10.2): keep data access behind one module so the export
   can swap the API for embedded data.

## Testing

- Unit/component tests for non-trivial UI logic (delta display, trace timeline layout).
- Playwright covers the E3 acceptance flow: list runs → compare two → open a regressed case → triage it; and opening
  an exported HTML file with no server.
- Tests run against a backend serving fixture run directories — never a real model.

## Commands

```
pnpm install
pnpm generate-client                 # after `uv run python scripts/dump_openapi.py` in backend/
pnpm typecheck && pnpm lint && pnpm test && pnpm build
pnpm e2e                             # builds, starts the fixture Viewer on 8722, runs Playwright
pnpm dev                             # 127.0.0.1:8721, proxies /api to a running `lite-eval view` on 8720
```
